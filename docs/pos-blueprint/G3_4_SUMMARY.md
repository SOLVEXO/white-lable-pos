## What G3.4 does
**Backend** (`api/pos/supply/…`, facade over the existing `purchase-orders` data — dashboard and till see the same suppliers and POs):
* **Suppliers:** profile with optional NTN / STRN, contact, payment terms; list with the payable balance.
* **Purchase orders:** `draft → approved → sent → partially received → received`, or `cancelled` / `closed short`. Approval goes through the permission matrix (`supply.po.approve`) with the per-store limit `purchaseOrderMinor` (default 1,000.00; a manager alone up to it, above it the owner). Per-store gap-free PO and receipt numbers (`PO-000001`, `GRN-000001`, counters in the creating transaction). Edits only before receiving starts (an edited approved/sent PO goes back to draft and needs approving again); after receiving, a new document.
* **Receiving** — one transaction: stock, location row, lots, stock adjustments (→ stock-ledger movements), weighted-average cost, PO line counters, the receipt document (append-only) and the supplier **bill**. Against an approved PO (a cashier may, at the PO cost — `supply.po.receive`) or without a PO (manager only, supplier + unit cost required). Partial receipts, good / damaged quantities, **strict per-line cap** (two tills receiving the same line: one wins, the other gets `OVER_RECEIPT`; the PO's `receiptRev` is written first so racing receipts serialize). Lot number required for lot-tracked products, expiry optional; optional supplier invoice number / date. A retried `requestId` returns the original receipt.
* **Weighted-average cost (D5) in minor units**: `round((on-hand × cost + received × unit) / (on-hand + received))`, tested at exponent 0 / 2 / 3, with different-cost receipts and receipts after sales. Damaged units do not move the average (they are claimed back). (The dashboard's older return path rounded costs to 2 decimals; it now rounds to the currency's exponent — identical at exponent 2.)
* **Supplier returns:** linked to a receipt (and the lot that came in on it, never more than that receipt brought in), reduce stock through the existing return service (stock-ledger movement, right lot), and write a **credit** entry on the supplier's ledger in the same transaction.
* **Payables:** append-only minor-only ledger per supplier (`bill`, `payment`, `credit`, `adjustment`); balance = Σ rows; **aging** current / 30 / 60 / 90+ (payments settle the oldest bills first; aged from the supplier invoice date when given).
* **Supplier payments:** method `cash` / `bank` / `other`, reference, `requestId`. **Cash** comes out of the open shift's drawer — a `cash_out` on the shift in the same transaction, so expected cash drops (reusable helper `pos-cash-out.util.ts` for G3.5); no open shift → `NO_OPEN_SHIFT`; more than is owed → `EXCEEDS_BALANCE`; above the manager's limit → owner. Bank / other are recorded only.
* **Permissions (matrix):** cashier — see receivable POs (no costs) and receive against an approved PO; manager — everything else; costs, payables, payments manager / owner only. `G3_PERMISSIONS_AND_LIMITS.md` regenerated.
* **Money contract:** every response with `…Minor` states `currency` + `currencyExponent` (a contract test runs over every manager-visible response, in KWD); a cashier's responses contain no money field at all.

**App** (`lib/app/modules/pos_supply`): suppliers list / profile (aging, recent POs and receipts) / create-edit; PO list (status chips) / detail (actions by status) / new-edit PO; receive screen (against a PO or without; good / damaged, lot + expiry up front for lot-tracked lines, supplier invoice); supplier return; payables; supplier ledger (running balance); pay-supplier sheet (cash needs an open shift — otherwise "Open a shift to pay cash"). Cashier: only the receivable-PO list and the receive screen, no money rendered. **Offline:** supply screens say "needs an internet connection"; the PO list shows the last synced copy read-only with "Last synced <time> — read only".

## Not verified / not built / decisions to know
* **Not run on a real device;** the date pickers (expiry / invoice date) are not exercised by widget tests; offline behaviour is covered by widget / unit tests, not by airplane mode on hardware.
* **Receipt without a PO** creates no ad-hoc PO (the receipt stands alone and bills the supplier) — simpler than the original idea; say if you want the ad-hoc PO.
* **Serial-tracked products** cannot be received at the till (`SERIALS_NOT_SUPPORTED` — use the dashboard so each serial is recorded). Unlimited-stock variants are refused.
* **Damaged-on-arrival units are billed** (the supplier invoices what shipped) and come back as a credit through a supplier return; the average cost is re-weighted by the good units only.
* **No payment above the owed balance** (no prepayments); no supplier-payment reversal / adjustment screen (the ledger supports `adjustment` rows, nothing writes them yet).
* The supplier-return sheet opens from a receipt row on the supplier profile; there is no standalone route.
* Payments in the daybook are G3.5 (the cash-out category `supplier_payment` is already on the shift row).
* The dashboard's PO PDF / email paths are untouched and do not know the new `approved` / `sent` statuses beyond listing them.
* Production: no data migration is needed (new collections and optional fields); the new unique index `(storeId, seq)` on receipts builds on an empty collection.
